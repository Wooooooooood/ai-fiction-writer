# Novel Writing — 写作核心

整合大纲、角色、知识库、进度、质检能力，提供从细纲到正文的完整写作流程。

> **核心原则**：先规划后写作，先质检后发布。每章必须经过「读上下文→写逻辑骨架→确认骨架→写细纲→确认细纲→写正文→逻辑扫描→质检→修改→定稿」十步流程。

## 工作区规范

```
.novel/
├── outline/
│   └── 细纲/              # 细纲目录
│       ├── ch{NN}-细纲.md # 当前章节细纲
├── characters/            # 角色档案
│   └── new/               # 新增配角档案
├── knowledge/             # 知识库
├── tracking/              # 追踪文件
│   ├── 伏笔.md
│   ├── 时间线.md
│   ├── 角色状态.md
│   └── 上下文.md
├── progress/
│   ├── progress.json      # 进度数据
│   └── slices/            # 章节切片回顾
│       ├── ch{NN}_slice.md
└── chapters/              # 正文目录
    └── vol{N}-{卷名}/
        └── ch{NN}-{标题}.md
```

## 两种工作模式

本 Skill 区分两种工作模式：

| 模式 | 触发词 | 流程 | 说明 |
|------|--------|------|------|
| **写作模式** | "写这一章""续写""开始写""创作" | 完整十步流程 + 微逻辑卡 + 四问 + HTML 注释 | 从零写新章节 |
| **修改模式** | "改一下""调整""替换""删除""润色""修" | 最小化修改 + 最小同步 | 修改已有内容 |

### 修改模式核心原则

1. **说改就改**：用户说"改"时立即执行工具操作，禁止只给文字建议。
2. **最小改动**：只修改用户明确指定的内容，不动细纲、不动大纲、不动已冻结状态。
3. **不走完整流程**：修改时不重写微逻辑卡、不重新过动作前四问、不主动跑完整质检。
4. **最小同步**：只同步与本次修改直接相关的元数据。
5. **小改动例外**：单次修改字数变化低于 500 字且未涉及关键设定时，可跳过字数元数据同步和脚本重跑。
6. **状态降级**：修改后若原状态为 `final`，自动降级为 `polishing`，但不自动触发完整质检。

### 修改模式执行清单

```markdown
- [ ] 确认用户修改范围（具体段落/句子/词）
- [ ] 执行修改（只改指定内容）
- [ ] 验证修改已生效
- [ ] 判断是否需要同步元数据：
  - 字数变化 > 500 字 → 必须同步 word_count / progress.json
  - 字数变化 10-500 字 → 建议同步
  - 涉及时间/地点/人物/信息 → 同步逻辑矩阵 / 知情边界
  - 涉及地图设定 → 重新生成 SVG/HTML
  - 涉及关键设定 → 同步 worldbuilding / 角色档案
- [ ] 在 .novel/tracking/修改记录.md 中记录
- [ ] 若用户要求质检，再走 humanizer / review；否则不主动跑
```

### 写作模式与修改模式对比

| 环节 | 写作模式 | 修改模式 |
|------|---------|---------|
| 微逻辑卡 | 必须填写 | 不重写 |
| 动作前四问 | 每段必须 | 不重新过 |
| HTML 注释 | 每段添加 | 按需更新 |
| 逻辑矩阵 | 章末生成 | 涉及逻辑变化时更新 |
| 知情边界 | 实时更新 | 涉及信息变化时更新 |
| 质检 | 完整 humanizer + review | 用户要求时才跑 |
| 字数同步 | 变化 > 500 字必须同步 | 小改动（<500字）可跳过 |

## 十步写作流程

### 第一步：读上下文（Read Context）

写作前必须按以下顺序、完整读取上下文。偷工减料会导致设定吃书、角色OOC、伏笔断裂。

#### 1.1 读取前 10 章切片（强制）

进入 `.novel/progress/slices/`，按顺序阅读 `ch{N-10}_slice` 到 `ch{N-1}_slice`：
- 若切片不存在，则通过阅读对应章节正文补全
- 重点关注：**人物状态变化轨迹、物质细节一致性、情感线进展、伏笔回收情况**

#### 1.2 精读前 5 章正文（强制）

阅读 `chapters/` 下最近 5 章完整正文：
- 目的：捕捉行文节奏、对话风格、描写密度、角色口癖
- **重点核对时间线**：
  - 记录每章关键事件发生的**具体时刻**（如"早上6:40""上午11:45"）
  - 记录上下午转换、日期切换的明确标记
  - 确保当前章开头时间不与上一章结尾时间冲突
  - 严禁出现"上一章已早上醒来，下一章还在睡觉"等时间倒流
- 重点核对：地点一致性、服装/外貌连续性、情感曲线是否跳步
- 记录任何与当前细纲冲突的细节

#### 1.3 读取当前章细纲与大纲（强制）

- `.novel/outline/细纲/ch{NN}-细纲.md`：当前章节的节拍、爽点、情绪曲线、钩子设计
- `.novel/outline/outline.md`：卷级大纲、多线交织要求、分叉事件标记
- 若细纲与正文前置细节冲突，优先与作者确认，不得擅自偏离

#### 1.4 读取世界观设定（强制）

路径：`.novel/worldbuilding/`

- [ ] 读取 `worldbuilding/world.md` 世界总览
- [ ] 读取当前章节涉及地点的地图档案（L1/L2/L3）
- [ ] 读取 `worldbuilding/timeline/calendar.md` 确认历法与当前故事日期
- [ ] 读取出场角色所属势力的档案 `.novel/worldbuilding/factions/{势力}.md`
- [ ] 读取相关规则体系：`.novel/worldbuilding/systems/{魔法/科技/经济/法律}.md`
- [ ] 读取相关文化禁忌：`.novel/worldbuilding/culture/taboos.md`
- [ ] 确认当前地点、势力关系、规则限制、文化禁忌

#### 1.5 读取角色/知识/追踪/进度

1. **角色状态**：出场角色的当前状态、关系、弧线阶段
2. **知识库**：时代背景、品牌对照、物价锚点
3. **追踪**：活跃伏笔、时间线、上下文摘要
4. **进度**：当前章节号、字数目标、质量要求
5. **时间线**：读取 `.novel/tracking/时间线.md`，确认本章故事日期和前后章时间衔接

**上下文注入模板**：
```
[大纲上下文]
当前章节：第 {N} 章《{标题}》
故事日期：{日期}
本章时间跨度：{起始时刻} → {结束时刻}
上一章结束时刻：{时刻}
节拍：{节拍列表}
爽点：{爽点类型} @ {位置}
情绪曲线：{情绪变化}
章尾钩子：{钩子描述}

[角色上下文]
{角色1}：{当前状态}，{性格标签}，{关系状态}
{角色2}：{当前状态}，{性格标签}，{关系状态}

[世界观上下文]
世界总览：{一句话}
当前地点：{城市/区域} — {地理特征}，{势力控制}
当前日期：{纪年} — {季节/节日}

禁忌：{文化禁忌}
地图状态：{已解锁地点 / 附近迷雾区域}

[逻辑状态上下文]
本章冻结时间：{时间}
本章冻结地点：{地点}
各角色冻结状态：
- {角色A}：{地点}，{情绪}，知道{信息}，不知道{信息}
- {角色B}：{地点}，{情绪}，知道{信息}，不知道{信息}

- {角色A}不知道{信息X}，不能表现出知道
- {角色B}知道{信息Y}，必须按性格反应
待解决问题：
- {问题1}
- {问题2}

[知识上下文]
时代/世界观：{设定}
注意：{品牌对照}、{物价锚点}、{禁用词}

[追踪上下文]
活跃伏笔：{伏笔列表}
需回收：{本章节需回收的伏笔}
需设置：{本章节需设置的新伏笔}

[写作要求]
字数：{目标字数}
POV：{视角}
多线：{主线/副线/交织}
```

### 第二步：写场景微逻辑卡（Write Scene Micro Logic Card）

**不写完整句子，只写场景内的动作链、因果链和信息变化。**

每个场景动笔前，必须填写 `.novel/logic/scene-cards/ch{NN}-scene{M}.md`：

```markdown
---
scene: {scene-01}
chapter: {NN}
location: {精确地点}
start_time: {HH:MM}
end_time: {HH:MM}
characters_present:
  - {角色A}: {位置}，{状态}，{知道什么}，{想要什么}
  - {角色B}: {位置}，{状态}，{知道什么}，{想要什么}
---

## 进入状态

- 时间：{时刻}
- 地点：{精确位置}
- 上一场景结束状态：{简述}
- 每个人此刻知道什么 / 不知道什么

## 动作链

1. **触发**：{谁 + 做什么}
   - 时间过了：{多久}
   - 地点变化：{无 / 从A到B}
   - 信息变化：{谁知道了什么}
   - 动作前四问：{通过/不通过}

2. **反应**：{谁 + 反应}
   - ...

3. **结果**：{谁 + 决定}
   - ...

## 退出状态

- 时间：{时刻}
- 地点：{是否变化}
- 在场人物及位置
- 每个人知道什么 / 不知道什么（更新后）
- 留下的悬念/钩子
- 下一场景衔接点
```

**微逻辑卡必须回答**：
1. 谁在场？每个人此刻在哪里、知道什么、想要什么？
2. 场景触发、反应、结果分别是什么？
3. 每个动作后时间过了多久？地点是否变化？谁知道/不知道什么变了？
4. 主角有没有越界？有没有说/做不该他做的？
5. 专业人员有没有各司其职？有没有问错人？
6. 世界观/地理/势力/感情线校验是否通过？
7. 这个细节后面用得上吗？前置条件是什么？
8. 数量/时间/材质合理吗？符合现实常识吗？

### 第三步：确认场景微逻辑卡（Confirm Scene Micro Logic Card）

**必须向作者展示微逻辑卡，获得确认后再写细纲。**

展示内容：
1. 场景进入状态和退出状态
2. 动作链及每个动作的时间/地点/信息变化
3. 爽点位置和释放方式
4. 章尾钩子设计
5. 主角边界检查清单
6. 专业人员各司其职检查清单
7. 信息边界变化清单

**禁止**：未确认微逻辑卡直接写细纲。

### 第五步：确认细纲（Confirm Beat Sheet）

**细纲完成后向作者展示，获得确认后再写正文。**

展示重点：

2. 对话要点是否自然
3. 爽点设计是否到位
4. 钩子是否符合预期

### 第六步：写正文（Write Draft）

根据确认后的细纲和场景微逻辑卡写正文，遵循以下规则：

**基本规则**：
1. 字数必须达标
2. 严格遵循细纲的节拍、场景、对话要点、爽点位置、钩子设计
3. 严格遵循场景微逻辑卡中的动作链、时间、地点、信息变化
4. 每章至少1个爽点
5. 章尾必须有钩子
6. 多线推进，不能连续3章只推一条线
7. 时间单位统一，避免"时辰"等不一致表达
8. **后台数字不进正文**：时间轴只用于细纲和切片辅助逻辑，正文禁止直接罗列策划数字。例外：特殊节日和关键时间节点，若用于推进剧情或情感转折
9. 涉及上下午转换时必须明确标注
10. 若细纲与前置正文存在冲突，必须按切片/正文事实修正细纲或向作者请示，不得直接在正文中吃书
11. 新增配角必须同步创建/更新 `.novel/characters/new/{角色名}.md` 档案，并写入当前细纲的出场角色列表
12. **新增地点/势力/规则/文化细节必须同步创建/更新 `.novel/worldbuilding/` 对应档案**
13. **角色行为必须符合所属势力/种族/职业/阶层设定，不得凭空创造未备案设定**
14. **地理移动必须合理**：从 A 到 B 的时间、交通方式、距离必须与世界building地图一致
15. **修改本章前必须联系前 5 章正文，确认人物状态、情节进度、关键设定未被推翻；修改后必须反向检查前章是否因本章改动而逻辑不一致**

**段落级硬阻塞规则**：
1. **写前四问**：每写一段正文前，必须回答：
   - 谁在场？
   - 他们刚在哪？
   - 他们为什么要这么做？
   - 这个信息/道具/称呼从哪来的？
2. **四问全部通过才能写下一段**。
3. **HTML 双轴标注**：每段正文前加注释：
   ```markdown
   <!-- LOGIC: time=09:15 | loc=公司会议室 | present=主角,李总 | info=主角知道B，李总不知道C -->
   ```
4. **即时更新知情边界**：任何信息传递、偷听、误解场景，写完后立即更新 `.novel/tracking/知情边界.md`。
5. **即时逻辑校验**：每写完一个场景，生成本场景即时逻辑报告，不通过则修改。
6. **章末生成逻辑矩阵**：每章写完后调用脚本：
   ```bash
   python3 .novel/scripts/generate_logic_matrix.py \
     chapters/vol{N}-{卷名}/ch{NN}-{标题}.md \
     -o .novel/tracking/逻辑矩阵.md
   ```
7. **定稿前清理 HTML 注释**。

**执行纪律规则**：
1. **说改就改**：用户说"改""替换""删除"时，必须立即执行工具操作，禁止只给文字说明
2. **区分写作/修改模式**：写作模式走完整十步流程；修改模式执行最小化修改，不走完整流程
3. **区分权限**："同步切片/tracking/progress"等元数据时，不得修改正文；"修改正文"时必须明确获得用户授权或响应用户明确指令
4. **修改后验证**：每次修改后必须验证改动已生效，未生效不得进入下一步
5. **字数同步**：
   - 字数变化 > 500 字：必须同步 front matter 的 word_count 和 `.novel/progress/progress.json`
   - 字数变化 10-500 字：建议同步
   - 字数变化 < 10 字：可忽略
   - 涉及关键设定、人物关系转折、时间线、专业细节的修改：无论字数多少都要同步
6. **修改模式最小同步**：只同步与本次修改直接相关的元数据，禁止全量重跑写作流程
7. **脚本调用**：章末或修改涉及逻辑/地图变化时，调用对应脚本生成/更新产物

**叙事规则**：
1. **POV规范**：主视角明确，切换时明确标记
2. **展示而非讲述**：用动作、表情、细节替代直接情感陈述
3. **五感描写**：视、听、嗅、味、触至少用到2种
4. **对话自然**：口语化、省略、打断、语气词
5. **避免模板**：不用"嘴角微微上扬""眼中闪过一丝"等套话
6. **克制修辞**：删除冗余修饰和过度比喻，用自然口语和精准动作替代
7. **避免自我解释型旁白**：少用"他知道""他意识到""他想"等解释句，多用动作、对话和反应呈现人物状态

---

### 第七步：逻辑扫描（Logic Scan）

**正文写完后，必须逐句过逻辑扫描，不能跳过。**

#### 7.1 人物能力边界扫描

对每句主角的台词/动作，回答：
- [ ] 这句话是不是具体执行指令？（时间/材质/重量/动作/参数）→ 如果是，改
- [ ] 这句话是不是抽象文艺表达？→ 如果是，改成大白话
- [ ] 这句话有没有暴露主角不该知道的信息？→ 如果是，改

#### 7.2 专业人员各司其职扫描

对每句专业人员的台词/动作，回答：

## 角色行为与用语规范

1. **写角色前先查档案**：动笔前读取 `.novel/characters/` 中出场角色档案，确认身份、职业、性格、dialect、关系
2. **职业决定行为**：禁止让角色做与职业身份冲突的行为
3. **情感要符合关系**：不能写与角色当前关系和情感档案冲突的心理或行为
4. **方言/粗口符合籍贯**：角色方言、粗口必须与其籍贯档案一致
5. **时代用语自然**：禁用不属于当前时代/世界观的词汇和轻佻中英夹杂
6. **解释性旁白黑名单**：删除"一个不会让人觉得他在抢风头的位置""这意味着""这说明""他是为了"等解释性描述

## 主角能力边界与专业分工规范

### 主角阶段定位

**当前阶段定位**：主角仅有{基础能力}，尚未获得{高级能力}。他能看到"对的方向"，但不一定懂"怎么执行"。

**表述边界**：
- 可以说："我想象中，画面是这样的……""给人的感觉应该是……""方向上应该是……"
- 不可以说：超出主角当前能力范围的具体执行指令、抽象文艺表达
- 被问到专业细节时的标准回应：
  - "这个您定。"
  - "具体怎么执行，老师们比我懂。"
  - "我只管方向，不管方法。"
  - "您看怎么好就怎么来。"

### 专业人员各司其职

1. **{决策者}**：拍板方向、协调分工、承担最终责任。不问主角具体执行参数。
2. **{专业角色A}**：负责{专业领域A}。
3. **{专业角色B}**：负责{专业领域B}。
4. **主角**：只负责描述"最终画面应该给观众什么感觉"，不回答上述任何专业领域的技术问题。

### 违规示例与修正

| 错误 | 问题 | 修正 |
|------|------|------|
| 主角："先全黑三秒，再突然一亮" | 具体时间不该他说 | 主角："先全黑，再突然一亮"；专业人员："三秒？" |
| 主角示范专业动作 | 不是专业人员，不该示范 | 专业人员自己调整，主角旁观 |
| 专业人员问主角技术细节 | 专业人员不该问外行 | 专业人员自己提出专业判断 |
| 决策者问主角技术参数 | 决策者不该问学生/外行技术参数 | 决策者问专业人员 |

## 白话文写作规范

1. **目标读者**：普通网文读者，非文艺爱好者。
2. **禁用表达**：
   - 文艺腔："尾音断在空气里""心跳跟着余韵跳""眼中闪过一丝……"
   - 抽象比喻："节奏是呼吸""声音是华夏的心跳"
   - 过度修辞："像头拉磨的驴""肉馅包子"
3. **推荐表达**：
   - 用具体动作替代抽象感受
   - 用大白话替代书面语
   - 用场景状态替代内心独白
4. **修改原则**：能删则删，能短则短。同一处反复修改超过两次，说明方向没定准，必须先确认再改。

## 逻辑自洽写作规范

每个场景下笔前，必须先回答五个问题：
1. **谁在场？** 列出所有在场角色，明确各自位置。
2. **他们刚在哪、做了什么？** 与前文时间、地点、动作无缝衔接。
3. **他们现在要做什么？** 动作目的明确，不为了凑字数而写。
4. **他们为什么这么做？** 动机符合人物身份、关系和当前情绪。
5. **这个细节有来源吗？** 每个道具、称呼、信息都要能说出从哪来。

写完后反向检查：
- 任何一个人物的行为，换到他的立场上是否还合理？
- 有没有哪句话、哪个细节，放到前章设定里会矛盾？
- 有没有为了修辞或爽点，硬加的不合理桥段？
- 人物称呼是否符合关系档案？
- 态度转变是否有铺垫？

## 避免重复写作规范

1. **同一信息只出现一次**：人物状态、背景说明、情感转折不要在同一章内反复写。
2. **删除重复段落**：同一动作、同一段心理、同一句式出现第二次时，必须删掉或改写。
3. **对话不重复表达同一意思**：一个人说完，另一个人不要再用不同的话复述一遍。
4. **切片与正文同步**：修改正文后，必须检查切片是否残留旧内容、旧对话、旧设定。
5. **章节之间不重复**：上一章已经写过的内容，本章不要从头再写，只写变化和新信息。
6. **称呼不重复解释**：人物关系已通过档案或前文交代，正文不要反复解释谁是谁。

## 相邻章节反重复检查

1. **搜索前文**：写任何标志性动作、神态、解释前，先搜索前 5 章是否已写过同类描写
2. **标志性动作只写一次**：标志性动作相邻章节只能出现一次；第二次出现必须换一种写法，或只保留动作不加解释
3. **解释性规则只建立一次**：解释性规则全文只需建立一次，后续章节直接写动作即可
4. **同一场景不重复铺陈**：上一章已写过的环境、氛围、人物状态，本章不要从头再写。

## 多线结构规则

1. 【{线A}】章节：{线A}推进为主，{线B}可信息出场
2. 【{线B}】章节：{线B}推进为主，{线A}可信息出场
3. 【交织】章节：多线共同出场，情感/事件推进
4. 交汇规则：{线A}每完成一个节点，{线B}就上一个台阶

## 爽点写作公式

1. **能力碾压型**：
   - 铺垫：展示作品世界常规水平（让读者知道标准）
   - 冲突：主角的方案被质疑
   - 释放：主角展示优势，全场震惊
   - 副作用：引来嫉妒或关注

2. **打脸反脸型**：
   - 铺垫：反派嚣张放话
   - 冲突：反派出手打压
   - 释放：打压适得其反，主角反而更火
   - 副作用：反派更恨，加大打压力度

3. **情感升温型**：
   - 铺垫：日常互动积累好感
   - 冲突：误会或外界阻碍
   - 释放：误会解除，关系突破
   - 副作用：新的挑战（公开、远距离等）

## 钩子写作技巧

| 类型 | 写作要点 | 示例 |
|------|---------|------|
| 悬念钩子 | 戛然而止，留未解之谜 | "他打开门，看到的却是——" |
| 危机钩子 | 突发的坏消息 | 电话响起，传来噩耗 |
| 揭秘钩子 | 揭露重要信息的前半句 | "其实，我早就知道你是——" |
| 期待钩子 | 铺垫好事即将发生 | 明天就是决赛，他准备好了 |
| 情感钩子 | 关系转折的前兆 | 她看着他，眼中第一次有了异样的光芒 |

## 章尾钩子简洁规则

1. 章尾钩子不超过两句，禁止用大段环境描写或内心独白代替钩子
2. 钩子可以是：一个动作、一句对话、一个发现、一个决定、一个悬念
3. 避免散文式收尾
4. 示例（好）："{角色}愣了一下，抬起头看向{主角}。" 示例（不好）："他收回目光，在心里默念了一遍……"

## 写作技巧库

### 开篇技巧（前500字）

1. **悬念开局**：直接抛出冲突或谜团
2. **场景开局**：用鲜明场景代入
3. **对话开局**：用对话展示关系
4. **动作开局**：用动作抓住注意力

**禁忌**：
- 大段背景介绍
- 慢节奏景物描写
- 无关紧要的人物出场

### 节奏控制

**快→慢→快节奏**：
- 快节奏：冲突、动作、对话
- 慢节奏：内心独白、情感描写、细节铺垫

**节奏切换信号**：
- 快→慢：冲突结束后，进入反思或情感
- 慢→快：铺垫完成，进入冲突或爽点

### 多线切换技巧

1. **时间同步切换**：同一时间点，切换两个场景
2. **因果切换**：A线的行动导致B线的反应
3. **悬念切换**：A线留悬念，切换到B线，稍后回来
4. **情感呼应**：A线的情感在B线得到呼应

### 爽点叠加技巧

1. **单层爽点**：一个爽点
2. **双层爽点**：事业爽点 + 情感爽点
3. **连锁爽点**：一个爽点触发下一个爽点
