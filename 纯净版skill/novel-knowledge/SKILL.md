# Novel Knowledge — 知识库管理

管理 `.novel/knowledge/` 下的**真实/考据型时代背景知识**，支持时间线对照、物价锚点、品牌对照、对标书管理与 Markdown+HTML 双备份。

> **核心原则**：知识库是作品世界一致性的最后防线，写作前必须查询，写作后必须校验。
>
> **与 novel-worldbuilding 的分工**：
> - **knowledge**：真实历史、物价、品牌、考据资料、参考文献
> - **worldbuilding**：虚构世界设定、地图、历法、势力、种族/职业、规则体系、文化禁忌
>
> 穿越题材中，「现实世界」由 knowledge 管理，「作品世界规则」由 worldbuilding 管理。

## 核心操作

### 0. 写作前时代背景查询

AI 写作或修改正文前，必须根据当前场景查询以下知识：
1. **时代用语**：当前时代是否已有该词汇/说法？禁用后世词
2. **社会常识**：场景是否符合时代背景（城市面貌、建筑状态、行业生态）
3. **籍贯方言**：角色籍贯决定其方言、粗口、习惯用语
4. **品牌对照**：正文中出现现实品牌必须替换为作品世界名称

**时代场景合理性规则**：
- 体制内/古风场景：庄重、专业，禁用轻佻中英夹杂
- 现代职场场景：可使用行业术语，但不宜过度网络化
- 家庭场景：符合当时生活水平
- 任何与时代明显冲突的细节必须向作者确认

### 1. 知识录入与编辑

用户通过对话提供知识 → 按规范生成 Markdown → 保存到对应分类目录。

### 2. 双备份同步

监听 `.novel/knowledge/**/*.md` 保存事件：
1. 读取 Markdown 文件
2. YAML frontmatter → HTML `<meta>` 标签
3. Markdown 正文 → HTML `<section>` 结构化内容
4. 生成同名 `.html` 文件

### 3. 品牌对照检测

扫描章节文本，检测现实品牌名称是否泄露：
- 对比 `.novel/knowledge/culture/品牌对照表.md`
- 标记违规：正文中出现"{现实品牌}"（应为"{作品世界品牌}"）
- 区分：内心独白可用现实名称，对话必须使用作品世界名称

**品牌对照表格式**：
```markdown
| 现实名称 | 作品世界名称 | 类型 | 首次出现 |
|---------|------------|------|---------|
| {现实} | {作品世界} | {类型} | ch01 |
```

### 4. 时间线对照

根据 `config.yaml` 的 `anchor_date` 计算：
- 故事第 N 天 = 锚点日期 + N 天
- 自动提示该日期附近的真实/设定事件

示例：
```
故事第 30 天 = {日期}
真实事件：{事件}
作品世界事件：{事件}
```

### 5. 物价锚点检测

扫描章节文本中的价格描述：
- 对比知识库中的历史/设定物价
- 标记合理性：`{年份}{地区}{物品}{价格}（✓合理）`
- 标记异常：`{年份}{地区}{物品}{价格}（✗异常，当时约{价格}）`

### 6. 与 novel-worldbuilding 的协作

**明确分工**：

| 内容 | 归属 Skill | 说明 |
|------|-----------|------|
| 真实历史事件 | knowledge | 如 1998 年金融危机、某个真实节日 |
| 虚构历史纪元 | worldbuilding | 如苍澜历、星际联盟纪元 |
| 真实物价/品牌 | knowledge | 如 1998 年猪肉价格、诺基亚手机 |
| 虚构货币/势力 | worldbuilding | 如灵石、东海商会 |
| 真实地理/城市 | knowledge | 如北京胡同、上海外滩 |
| 虚构地图/城市 | worldbuilding | 如东海城、星际空间站 |
| 考据资料 | knowledge | 参考文献、历史文献 |
| 虚构规则/魔法 | worldbuilding | 修炼体系、科技树 |

**协作流程**：
1. 写作前，同时查询 knowledge（真实背景）和 worldbuilding（虚构设定）
2. 穿越题材中，穿越者/知情角色内心可用现实知识，但对话中必须符合作品世界设定
3. 若真实知识与虚构设定冲突，以 worldbuilding 为准（worldbuilding 是作品世界内的 Source of Truth）

### 7. 对标书管理

**对标书作用**：
- 学习爆款作品的开篇力、爽点设计、人设塑造
- 定期对比本书与对标书的差距
- 识别改进空间

**对标维度**：
| 维度 | 说明 | 权重 |
|------|------|------|
| 开篇力 | 前500字吸引力 | 20% |
| 爽点密度 | 每章爽点数量 | 20% |
| 人设鲜明 | 角色记忆度 | 15% |
| 节奏感 | 情节推进速度 | 15% |
| 期待感 | 追更动力 | 15% |
| 文笔 | 描写质量 | 15% |

**对标流程**：
1. 选择对标书（同类型爆款）
2. 逐章对比分析
3. 识别差距和改进点
4. 将改进建议融入大纲

### 8. 知识库检索

用户输入关键词 → 检索所有 `.md` 文件：
- 优先匹配 `event`、`item`、`name` 字段
- 返回相关知识条目 + 来源

### 9. 知识使用记录

```json

```
