# Novel Outline — 大纲编排

管理 `.novel/outline/` 下的大纲文件，支持多线对比、蝴蝶效应追踪、爽点设计与情绪曲线规划。

> **核心原则**：大纲是骨架，正文是血肉；细纲是参考，不是枷锁。

## 工作区规范

```
.novel/
├── outline/
│   ├── outline.md          # 人编辑（Source of Truth）
│   ├── outline.html        # AI 消费（自动同步）
│   └── 细纲/              # 细纲目录（详细版）
│       ├── ch{NN}-细纲.md  # 每章独立细纲
│       └── ...
└── tracking/
    └── outline-changes.json  # 大纲变更记录
```

## 大纲与正文的关系

1. **细纲是参考，不是枷锁**：正文写作中，用户有权随时调整爽点强度、伏笔释放节奏、角色反应。AI 不得固守原细纲而拒绝用户修改。
2. **爽点升级/降级随用户**：用户说"爽点爆发"就升级，用户说"爽点降级"就降级，无需死守原计划。
3. **伏笔释放节奏随用户**：原计划"ch10 释放"，用户要求"ch07 释放"，则按用户要求执行，并同步更新伏笔状态。
4. **调整留痕**：任何与原细纲的偏离，必须在 `.novel/tracking/修改记录.md` 中说明，并同步更新大纲/切片/伏笔。

## 核心操作

### 1. 大纲编辑

支持三级结构：
- **卷**（Volume）：故事大阶段
- **章**（Chapter）：具体章节
- **节拍**（Beat）：章节内的情节节点

### 2. 多线结构

作品可采用多线结构：
- **A线（主线）**：{主线描述}
- **B线（副线）**：{副线描述}

**交织规则**：
- 每章至少有一条线推进
- 主线/副线交替进行，不能连续3章只推进一条线
- 交汇点：共同出场、互相影响、情感升级

**章节标签**：
- 【{线A}】—— 主要推进线A
- 【{线B}】—— 主要推进线B
- 【交织】—— 多线共同推进
- 【爽点】—— 本章有爽点设计
- 【钩子】—— 本章有钩子/伏笔

### 3. 爽点设计（每章必须）

**爽点类型库**：
| 类型 | 说明 | 适用场景 |
|------|------|---------|
| 能力碾压 | 用信息差/能力差吊打对手 | 展示、比赛、评审 |
| 身份揭露 | 隐藏身份被意外发现 | 马甲掉落、真相大白 |
| 打脸反派 | 反派打压→适得其反 | 反派相关 |
| 情感升温 | 男女主关系突破 | 暧昧→确认→甜蜜 |
| 资源获取 | 获得关键资源/人脉 | 签约、投资、版权 |
| 危机化解 | 绝境中逆转 | 危机场景 |
| 意外走红 | 无心插柳柳成荫 | 传播、走红 |

**爽点设计模板**：
```markdown
#### 爽点设计

- **爽点类型**：{类型}
- **爽点位置**：{节拍编号}
- **爽点强度**：{1-10}
- **读者情绪**：{情绪变化}
- **铺垫**：{前置铺垫}
- **释放**：{爽点场景}
- **副作用**：{爽点带来的新问题}
```

### 4. 情绪曲线设计

每章必须规划情绪曲线，避免平淡：

```markdown
#### 情绪曲线

| 位置 | 情绪 | 强度 | 说明 |
|------|------|------|------|
| 开头 | {情绪} | {1-10} | {说明} |
| 中段 | {情绪} | {1-10} | {说明} |
| 转折 | {情绪} | {1-10} | {说明} |
| 爽点 | {情绪} | {1-10} | {说明} |
| 结尾 | {情绪} | {1-10} | {说明} |
```

**情绪设计原则**：
- 情绪必须有起伏，不能全程平坦
- 爽点前必须有压抑/紧张（先抑后扬）
- 章尾情绪应为「期待」或「悬念」，引导追更
- 连续两章的情绪峰值不能相同

### 5. 钩子规划

每章必须设计章尾钩子：

```markdown
#### 钩子

- **章尾钩子**：{描述}（**{类型}**）
- **回收章节**：{章节号}
- **预期效果**：{读者反应}
```

### 6. 分叉点标记

任何节拍可标记为 **分叉点**，记录：
- **原历史**：未受主角干预的走向
- **新历史**：主角干预后的走向
- **触发条件**：什么行为导致分叉
- **影响章节**：哪些后续章节会因此改变

### 7. 蝴蝶效应追踪

在章节末尾记录 **蝴蝶影响**：
```markdown
#### 蝴蝶影响

- 第 X 章：{影响描述}
```

### 8. 细纲

每章独立细纲文件 `.novel/outline/细纲/ch{NN}-细纲.md`：

```markdown
---
chapter: {N}
title: "{章节标题}"
story_date: "{日期}"
word_target: "{字数范围}"
pov: "{视角}"
---

## 场景列表

1. **场景1**：{场景名称}
   - 时间：{具体时刻}
   - 地点：{地点}
   - 角色：{出场角色}
   - 目标：{场景目标}
   - 冲突：{冲突描述}
   - 结果：{结果}
   - 情绪：{情绪}→{情绪}

## 对话要点

- {角色}："{关键对话}"（{对话作用}）

## 关键描写

- {描写对象}：{描写要点}

## 情感线

- {角色}：{情感变化}
```

### 9. 影响分析

当用户调整大纲（删除/移动/修改章节）时：
1. 提取该章节的所有伏笔标记、角色出场、分叉事件
2. 分析前后章节的依赖关系
3. 生成影响报告

当用户调整世界设定（地点、势力、规则、文化）时：
1. 提取受影响的地点、势力、规则、文化条目
2. 扫描 `chapters/` 和 `worldbuilding/` 中引用这些设定的章节
3. 分析角色行为、剧情发展、地理移动是否需要同步调整
4. 生成世界设定影响报告，标记需重新质检的章节

### 10. AI 生成约束

续写时注入大纲上下文：
```
[大纲上下文]
当前章节：第 {N} 章《{标题}》
故事日期：{日期}
本章节拍：{节拍列表}
当前节拍：{当前节拍}
爽点类型：{类型}
情绪曲线：{情绪变化}
出场角色：{角色列表}
世界观约束：{地点/势力/规则/文化限制}
章尾钩子：{钩子描述}
```

## 大纲状态

章节状态流转：
- `planned` — 已规划，未开始写
- `draft` — 草稿中
- `revised` — 已修订
- `final` — 定稿
