# AI 小说创作助手 —— VSCode 插件 PRD（通用版）

> **版本**：V1.0（通用抽象版）
> **目标平台**：VSCode Extension（本地离线优先）
> **适用题材**：通用，可配置为都市穿越、玄幻、科幻、言情等
> **核心原则**：零服务端、文件即数据、Skill 化拆解、Markdown+HTML 双备份

---

## 一、背景

当前市面 AI 写作工具以 SaaS 形态为主，存在数据隐私风险、角色记忆断层、AI 味浓重、无法适配特定题材特有痛点（时代错位、蝴蝶效应、物价锚点、世界观一致性）等问题。个人需要一个完全本地化、可 Git 管理、模块化的 VSCode 插件，将创作流程拆解为可独立调用的 Skill，实现"人主导 + AI 辅助"的协同模式。

## 二、目的

构建一套基于 VSCode 的本地 AI 小说创作工具，通过 Skill 化架构将创作流程解耦为独立功能单元，以 Markdown+HTML 双备份机制保障知识库的可维护性与 AI 消费友好性，最终解决小说创作中的进度失控、角色崩坏、设定错位、AI 味浓重四大核心痛点。

## 三、目标

1. **架构目标**：核心模块以独立 Skill 形态存在，支持按需调用、自由组合；
2. **数据目标**：所有创作数据（正文、配置、知识库）以本地文件形式存储，100% 可 Git 追踪；
3. **知识库目标**：实现 Markdown（人编辑）+ HTML（AI 消费）双备份，每次操作后自动同步；
4. **体验目标**：写作时自动注入角色卡+知识库上下文，去 AI 味检测评分响应时间 < 3s；
5. **题材目标**：内置可配置的检测维度（时代错位、物价锚点、蝴蝶效应追踪等）。

## 五、Skill 拆解设计

### Skill-1：进度管理（Project Navigator）

**定位**：章节导航、字数追踪、状态标记、写作日历、钩子追踪。

**触发条件**：
- 主动：用户点击侧边栏"进度"面板；
- 自动：每次保存 `.md` 文件时更新字数统计；
- 定时：每日 00:00 生成昨日写作报告。

**输入**：
- `chapters/` 目录下的所有 `.md` 文件；
- 用户手动标记的章节状态（未写/草稿/精修/定稿）。

**处理流程**：
1. 扫描 `chapters/` 目录，按文件夹（卷）+ 文件（章）构建树形结构；
2. 读取每章 Markdown 字数（中文字符数）；
3. 累加总字数、卷字数、今日字数；
4. 对比 `config.yaml` 中的 `daily_target` 和 `total_target`；
5. 生成进度报告。

**输出**：
- 侧边栏树形视图（章节 + 状态图标 + 字数）；
- 状态栏实时显示：`今日 X 字 / 目标 Y 字 | 第 N 章 | 故事时间：{日期}`；
- 底部面板写作报告（本周趋势、日均字数、预计完本日期、钩子状态）。

### Skill-2：角色档案管理（Character Keeper）

**定位**：角色档案、穿越者双重身份（如适用）、关系图谱、角色弧线、言行一致性检测。

**触发条件**：
- 主动：用户创建/编辑角色卡；
- 主动：用户选中角色名右键"查看档案"；
- 自动：保存章节时扫描角色名，触发一致性检测；
- 写作时：AI 生成前自动注入相关角色上下文。

**处理流程**：
1. **档案编辑**：用户在 Webview 表单中填写角色信息 → 保存为 Markdown（YAML frontmatter + 正文）；
2. **双备份同步**：Markdown 保存后，自动渲染为 HTML（保留 YAML 为元数据注释），存入同名 `.html`；
3. **一致性检测**：扫描当前章节文本，提取角色对话/行为，对比角色档案中的 `speech_pattern` 和 `risk_rules`，生成警告列表；
4. **上下文注入**：AI 续写时，检索当前章节出场角色 → 读取对应 `.html` → 注入 Prompt。

### Skill-3：知识库管理（Knowledge Librarian）

**定位**：时间线对照、物价锚点、流行文化、品牌对照、参考文献 RAG、Markdown+HTML 双备份。

**触发条件**：
- 主动：用户创建/编辑知识库条目；
- 主动：用户选中文本"查证知识库"；
- 自动：写作时输入故事内日期，自动提示对应设定事件；
- 自动：每次知识库文件保存后，触发双备份同步。

**处理流程**：
1. **知识录入**：用户新建/编辑 `.md` 文件 → 保存；
2. **双备份同步**：监听 `.novel/knowledge/**/*.md` 保存事件，调用 Markdown→HTML 转换器；
3. **时间线对照**：根据 `config.yaml` 的 `anchor_date` 计算故事内日期；
4. **物价锚点检测**：扫描章节文本中的价格描述，对比历史物价；
5. **品牌对照检测**：扫描地球/现实品牌是否误用；
6. **参考文献 RAG**：用户上传资料转换为 Markdown → 切分 → 本地 Embedding（sqlite-vec）。

### Skill-4：大纲编排（Outline Architect）

**定位**：卷章结构、双时间线/多线大纲、蝴蝶效应分叉、节拍编辑、爽点设计、情绪曲线、钩子规划。

**触发条件**：
- 主动：用户在大纲面板增删改章节节点；
- 主动：用户拖拽章节调整顺序；
- 主动：用户标记"分叉事件"；
- 自动：用户修改大纲后，提示"影响分析"。

**处理流程**：
1. **大纲编辑**：用户在 Webview 中编辑三级结构（卷→章→节拍）→ 保存为 Markdown；
2. **双备份同步**：自动同步为 `.html`，供 AI 消费；
3. **分叉标记**：用户标记某节拍为"蝴蝶效应分叉" → 记录原历史、新历史、触发条件、影响章节；
4. **影响分析**：当用户调整大纲时，提取伏笔、角色出场、分叉事件，分析依赖关系，生成影响报告；
5. **AI 生成约束**：续写时注入大纲上下文，确保不偏离主线。

### Skill-5：世界构建（Worldbuilding）

**定位**：世界观、动态地图、历法、势力、种族/职业、规则体系、文化禁忌管理。

**触发条件**：
- 主动：用户初始化世界观；
- 主动：用户新增/编辑地点、势力、规则；
- 自动：每章写完后扫描正文，生成地图升级建议；
- 自动：写作前注入世界观上下文；
- 主动：用户申请修改带锁核心设定。

**输入**：
- `.novel/worldbuilding/` 下的所有设定文件；
- 当前章节正文；
- 角色档案中的 faction/race/profession 字段。

**处理流程**：
1. **初始化**：根据题材模板生成 worldbuilding 目录结构；
2. **动态地图**：扫描正文提取地名 → 生成升级建议 → 作者确认 → 更新地图档案 + SVG/HTML；
3. **设定锁**：核心设定写入后标记 `locked: true`，修改需走变更流程；
4. **上下文注入**：写作/审稿时注入 `[世界观上下文]`；
5. **一致性校验**：检测地点、势力、规则、地理移动是否与世界设定冲突。

**输出**：
- 结构化世界设定档案（Markdown + JSON + SVG + HTML）；
- 地图升级建议清单；
- 设定变更影响报告；
- 世界观一致性质检结果。

### Skill-6：逻辑预防（Logic）

**定位**：在写作过程中预防时间矛盾、空间瞬移、信息穿帮、行为越界、因果断裂。

**触发条件**：
- 自动：用户开始写新章节时生成本章冻结状态；
- 自动：用户开始写新场景时检查微逻辑卡；
- 自动：用户写下一段时触发动作前四问；
- 主动：用户请求生成逻辑矩阵或检查逻辑一致性。

**输入**：
- 前 5 章正文、前 10 章切片；
- `.novel/tracking/角色状态.md`、`.novel/tracking/知情边界.md`、`.novel/tracking/时间线.md`；
- `.novel/worldbuilding/map/*.json`（地理数据）。

**处理流程**：
1. **冻结状态**：写本章前提取关键状态，生成 `logic-state.json`；
2. **微逻辑卡**：每个场景动笔前强制填写；
3. **动作前四问**：每写一段正文前强制回答；
4. **HTML 双轴标注**：每段正文前加时间-地点-人物注释；
5. **即时逻辑校验**：每段/每场景写完后即时校验；
6. **逻辑矩阵**：每章写完后生成时间-地点-人物矩阵。

**输出**：
- `.novel/logic/scene-cards/` 微逻辑卡；
- `.novel/logic/paragraph-checks/` 四问记录；
- `.novel/tracking/知情边界.md`；
- `.novel/tracking/逻辑矩阵.md`；
- `.novel/logic/reports/` 逻辑检查报告。

### Skill-7：去 AI 味质检（Humanizer）

**定位**：AI 味检测、时代错位扫描、角色 OOC 检测、评分报告、人化改写。

**触发条件**：
- 主动：用户点击"质检当前章"；
- 主动：用户选中段落"检测选中"；
- 自动：保存章节时（可配置）触发快速扫描；
- 主动：用户点击"人化改写"。

**处理流程**：
1. **规则扫描**：时代错位词、系统面板化、数据流式叙述、情感标签化、对话说明书化、描写模板化；
2. **LLM 深度评估**：文学性、节奏感、角色一致性、对话自然度、场景沉浸感等；
3. **生成报告**：问题列表 + 评分雷达图 + 修改建议；
4. **人化改写**：保留情节、重述表达，提供 Diff 对比。

### Skill-8：扫榜与拆文（Analyze）

**定位**：市场趋势分析、对标书拆解、文风提取、个人模块库。

**处理流程**：
1. **扫榜**：分析热门榜单趋势（题材、人设、切入点、爽点密度、更新策略）；
2. **拆文**：深度拆解对标书，输出六维评分、角色、剧情、设定、文风分析；
3. **模块库**：将可复用套路沉淀到 `.novel/benchmarks/`。

**定位**：整合大纲、角色、知识库、进度、质检能力，提供从细纲到正文的完整写作流程。

**处理流程**：见 `novel-writing/SKILL.md`。

### Skill-10：多视角审稿（Review）

**定位**：编辑视角、读者视角、平台视角、作者视角四维度审稿，毒点排查。

**处理流程**：
1. **编辑视角**：商业价值、节奏、钩子、爽点；
2. **读者视角**：代入感、期待感、情绪满足、弃书风险；
3. **平台视角**：目标平台推荐机制适配；
4. **作者视角**：设定一致性、伏笔回收、角色 OOC、时间线、细节逻辑一致性。

## 六、核心机制：Markdown + HTML 双备份

### 6.1 设计原则

- **Markdown 是 Source of Truth**：人类唯一编辑入口，支持 Git diff、版本回退；
- **HTML 是 AI 消费层**：LLM 读取 HTML 格式，结构清晰、保留元数据；
- **单向同步**：Markdown → HTML，禁止直接编辑 HTML。

### 6.2 同步触发时机

1. **即时同步**：用户保存 `.md` 文件时，200ms 内完成 HTML 生成；
2. **批量同步**：插件启动时，扫描所有 `.md` 检查对应 `.html` 是否存在/过期；
3. **强制同步**：用户执行命令"Rebuild All HTML"。

### 6.3 转换规范

- YAML frontmatter → HTML `<meta>` 标签；
- Markdown 正文 → HTML `<section>` 结构化内容；
- 表格 → HTML `<table>`；
- 代码块 → 保留 `<pre><code>`。

### 6.4 冲突处理

- 若发现 `.html` 比 `.md` 新，提示"HTML 已被手动修改，是否覆盖？"；
- 若 `.md` 被外部编辑器修改，启动时自动检测并同步。

## 七、AI 上下文注入流程

当用户请求 AI 续写/润色时，Context Assembler 按以下优先级组装 Prompt：

```
[系统指令] 你是一位小说写作助手...

[大纲上下文]（来自 Skill-4 HTML）
当前章节：第 X 章《标题》
故事日期：{日期}
本章节拍：进入→冲突→转折→退出
分叉状态：已分叉/未分叉

[角色上下文]（来自 Skill-2 HTML）
出场角色：{角色名}（主角）
- 当前身份：{身份}
- 语言风格：{风格}
- 禁忌：{禁忌}

[知识库上下文]（来自 Skill-3 HTML）
时间线：{日期}，事件：{事件}
物价锚点：{物价}
参考文献：{RAG 检索结果}

[前文摘要]（最近 2000 字压缩）
...

[用户输入]
续写：...
```

## 八、非功能需求

1. **性能**：双备份同步延迟 < 300ms；去 AI 味规则扫描 < 1s；LLM 评估 < 5s；
2. **兼容性**：支持 Windows/macOS/Linux；支持 VSCode 1.80+；
3. **隐私**：所有数据本地存储，LLM 调用可切换本地 Ollama（完全离线）；
4. **可扩展**：知识库、角色卡、大纲均支持自定义模板，规则库支持用户扩展；
5. **Git 友好**：所有数据为文本文件，天然支持版本控制。
